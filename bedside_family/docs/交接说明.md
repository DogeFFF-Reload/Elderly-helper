### 4.1 语音开放理解(接 LLM agent)——意图白名单已定版
- **agent 只做三件事**(任务书,超出即 none+礼貌回话,不得自选其他动作):
  1. **递东西**:"拿XX"任意物品→ 视觉识别 → 臂过去夹给他;
  2. **还回原位**:把手上的/拿过的东西放回原处;
  3. **归位**:臂+手回到 home。
- 接口位置:`arm_service.py` 的 `voice_cmd(pcm)`。升级形态:vosk **免词表转写**(grammar=None)或云端 ASR → 文本交 LLM(联网 API)→ 结构化意图 JSON `{action ∈ {pick_item, put_back, reset} | none, object:"物品名", reply:"给老人的回话"}` → 分发执行(object→视觉夹取,action→arm_execute/do_pose)。
- **防误触双保险**:①触发口唯一=屏上语音键后的 4 秒窗口,闲聊不进链路;②LLM 只能从上述三个动作选,none/无效=礼貌回绝——理解开放、执行封闭,乱抓乱按 structurally 不可能。
- **旧意图处理**:`press_sos`(按铃/救命)从语音里**拿掉**,只留屏上实体键;"递药/还药"被"拿XX/还回原位"泛化覆盖,词表同步清理。
- **无网保底**:LLM 调用失败自动回退关键词模式(词表法),演示场地断网也不断功能。
- T5AI 固件**零改动**(仍是录音 POST);可选后续:用 T5AI 喇叭播 agent 回话(TTS→WAV 随 /voice_cmd 响应返回,固件加一段播放,工作量小)。

## 六、踩坑要点(血泪浓缩)

- **T5AI(TuyaOpen/LVGL 线程模型)**:`lv_vendor_disp_lock` 非递归,LVGL 回调里绝不能再拿(死锁)=回调只置标志/切图,HTTP 全在 loop() 单线程串行;PCM 裸流 POST 必须用底层 `http_client_request_t`(.body_length 自填),封装版 strlen 会截断;Audio 库大缓冲必须 `tal_psram_malloc`;板载 mic 16k/16bit/mono 与 vosk 同规格零转码。
- **X5**:突发断电易卡死(今天两回);RNDIS 对端 IP 提权才可配;X5 半死时 T5AI 的 POST 会阻塞 loop 约 30s(屏不卡,独立线程);X5 侧 vosk pip 在线装就通(0.3.45),模型用 zip 推(SFTP 22-30s)。
- **安全**:应急停=拔 24V;手电源顺序 USB→20s→24V;力控阈值已限 500g 不夹碎药盒。
- **两板不联动**:S3 和 T5AI 今晚都指向 .251=同一只手#1(拍板过的),明后天原板回来再拆:改 unit.env + S3 固件 ARM_HOST 重烤。

## 七、S3 手板留言系统(v5.4,当晚已全链路实测)——老人侧

> 拓扑:嘉立创 S3 屏(COM7=烧录 / COM8=日志,CH340K 115200)↔ X5#A 手板(.252,服务端口 8013)。
> 烧录命令:`D:\arduino-cli\arduino-cli.exe` compile/upload --fqbn `esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=huge_app` -p COM7(exit=0 为过;S3 走 huge_app 无 OTA 分区)。

**按键(六键,新版)**:`[招手 | 手指操 | 猜拳 / 留言 | 听留言 | 语音]`。归位键已从屏上去掉(语音说"归位"仍执行);语音键挪到最末位。

**留言流向(语义定版,别再搞混)**:
| 方向 | 谁发起 | 文件 | 谁收听 |
|---|---|---|---|
| 老人→家属 | 老人点「留言」:点一下开录(蓝条),再点一下发送,语音键=取消,满 60s 自动发 | `msg_*.wav`(16k/16bit/mono) | **家属端 app** 拉 /messages 播放,**老人端不播自己** |

**留言是原声语音,不转文字**(拍板过的,家属听到的是老人本人声音)。

**播放链路(v5.3 修通)**:ES8311(I2C 0x18,slave I2S)+ 板载功放 PCA9557 BIT1。I2S0 STD 16k/16bit 立体声,MCLK 4.096M(×256),BCK14/WS13/DOUT45。**播放/录音共用 I2S0 永不同时用**:spk_start 先 mic_teardown,下次 mic_init 自动重建。

## 九、S3/X5#A 侧踩坑(血泪浓缩,当晚亲历)

1. **v5.2→v5.3 大事故(已根治,教训值千金)**:`spk_play_pcm` 用 int16 成对写 `stereo[2k]/[2k+1]`,被编译器合并成 32-bit 宽存储,尾部越界一格砸中 .bss 紧贴的 `s_spk_chan`,句柄被写成样本值 0xfffefffe → `i2s_channel_write` LoadProhibited **死循环重启,按键全灭**(屏还亮=崩前最后一帧,易误判"板子活着")。定位三板斧:串口抓 panic(Guru Meditation+backtrace+EXCVADDR)→ `xtensa-esp32s3-elf-addr2line` 解 backtrace(工具在 `Arduino15\packages\esp32\tools\esp-x32\2601\bin`)→ **`.ino.map` 查全局变量落点**(符号紧贴=越界实锤)。修复=u32 单元素逐帧写+8 帧垫料。**以后凡是"全局变量变成音频样本值",先查相邻缓冲区越界。**
2. **部署路径**:服务实跑 `python3 -m hand_controller.arm_service`,真身=`/root/caremate/hand_controller/arm_service.py`;顶层 `/root/caremate/arm_service.py` 是死文件别推。改服务后 `systemctl restart arm_service`,journalctl 无业务日志,看 `/status` 的 recent[](message_out=老人留言落盘;family_in=家属回话;pull_ok/pull_fail=拉取;voice_out 带"(agent)"=LLM 判定)。
