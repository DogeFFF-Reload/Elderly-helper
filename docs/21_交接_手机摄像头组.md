## 3. 任务队列（今晚全部可完成）

### T1 手机端：开流

1. 应用商店装 **IP Webcam**（Pavel Khlebovich，免费，约 10MB）
2. App 内设置 → 视频首选项：
   - 分辨率 **640×480**、画质 **70%**、帧率默认
   - **锁屏继续推流=开**（或保持 App 前台+关省电）
3. 点底栏"启动服务器" → 屏幕出取景框+**记下地址**：`http://192.168.x.x:8080`
4. **验证**：笔记本浏览器开 `http://192.168.x.x:8080` → 应见画面+控制页

**回执点**：流地址、笔记本能否见画面（截图）

### T2 电脑端：环境

```powershell
pip install pillow --quiet        # 一次性, 需联网
cd <解压>\code\camera
```

### T3 试机模式（--arm 0，只看数据不触发）

```powershell
python phone_fall_watch.py --phone http://192.168.x.x:8080 --arm 0
```

**预期**（控制台每几行一次）：
```
==== CareMate 手机哨兵 v0 ====  phone=http://...:8080 master=... arm=0
[M] e=  3.2 >──■ 重心=0.51
[M] e=  7.8 >────■ 重心=0.62
```
- `e=` 动作能量：**安静时应低于 10**；在镜头前挥手应 >25；**缓慢倒地动作应 >40**
- `重心=0.6x`：画面变化集中的高度（0 顶 1 底）
- 若 `[NET] 手机串流不通`：App 没开/不同网/IP 变了——回到 T1

### T4 校阈值（现场三分钟定稿法）

| 测试 | 记能量值 |
|---|---|
| 全静 10 秒 | a（例 2~6） |
| 正常走动/摆手 5 次 | b（例 20~35） |
| **缓慢倒地** 3 次 | c（例 45~70） |

阈值选法：**thresh = b_max + (c_min − b_max) × 0.4**（例 35~45 之间取 38）
→ 最终命令示例：`--thresh 38 --cooldown 30 --arm 1`

### T5 正式触发验收（--arm 1）

```powershell
python phone_fall_watch.py --phone http://192.168.x.x:8080 --master http://127.0.0.1:8000 --thresh 38 --arm 1
```

master 必须已在跑。**人缓慢倒地一次**：
```
[FALL ARMED] >>> 疑似跌倒! 已通知主脑(st=200) ...
```
**联动全套预期**：master 独白"您还好吗"（播报）→ 5 秒无回应 → 升级
"已按求助键/通知家属" → **机械手#2 自动轻握节拍（若手#2组在位）** →
大屏红警 → 女儿端"客厅跌倒"弹窗。

### T6 稳定性三连（演出标准）

连续完整触发 3 次：**0 误报、0 漏报**。误报→thresh+5 复测；
漏报→thresh−5 复测；仍不收敛→回执（附三组能量数据）。

## 6. 排错手册

| 症状 | 首查 | 药方 |
|---|---|---|
| `[NET] 手机串流不通` | App 关了/不同网/省电杀 | App 前台+常亮+同热点；IP 变了重查 |
| e 值恒 0 | 画面没动/取景固定物 | 挥手测试；重取景对准活动区 |
| 一直 [FALL?] | 阈值太低/灯闪/画面抖动 | thresh+5~10；固定手机；遮强光直射 |
| master 没反应(上报 200 但无动作) | master 没跑/端口错 | 先 `curl <master>/ping`；确认 :8000 |
| 触发后动作不完整 | 下游组(A/B组)没起 | 跟床头盒组/手#2组对时序——**不是你的锅**，回执注明 |
