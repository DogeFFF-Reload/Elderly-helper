# 家属端 App 对接需求单 —— 老人留言功能(发给队友)

> 项目:Mocen CareMate 养老陪伴机械手
> 发起:用户手板侧(S3 屏 + X5 手板,10.153.47.252)
> 请队友看完第 1 节,再按第 4 节的问题清单逐条回复即可,不急。

---

## 1. 一句话需求

老人在手 S3 屏上按一下「留言」键,对着屏幕说话(最长 60 秒,说完再按一下即发送);
**家属端 App 不点任何东西就能收到这条留言并播放**(最好有新留言提醒)。

老人侧流程(用户侧已定,不用队友管):

```
按「留言」键(替换原点赞键) → 屏显"正在留言…" → 再按一下=发送(或满60秒自动发)
→ 手板收存为带时间戳的 WAV(16k/16bit/单声道) → 转发给家属端
```

---

## 2. 用户侧(手板)能提供的

| 能力 | 说明 |
|---|---|
| 留言文件 | WAV,16kHz/16bit/单声道,≤60 秒,文件名含日期时间(如 msg_20261024_1930.wav) |
| 元数据 | 时间戳、时长(秒)、序号;以后可扩展老人身份 ID |
| 主动POST | 手板可以每收到一条新留言就 HTTP POST 到**队友指定的接口**(推荐方式) |
| 局域网拉取 | 手板上开两个 GET 接口(见第 3 节),同热点的手机/app 可来拉 |
| 安全约定 | 内网演示阶段先不设鉴权;若走公网再加一个固定 Token 头即可(约定字段 `X-CareMate-Token`) |

## 3. 手板侧接口规格(草案,建好后可直接联调)

```
GET  http://10.153.47.252:8013/messages
     → {"ok":true,"messages":[
          {"id":"msg_20261024_1930","time":"2026-10-24 19:30:05","duration":23.5},
          ...]}           按时间倒序,新留言在前

GET  http://10.153.47.252:8013/messages/msg_20261024_1930.wav
     → 直接返回音频文件(WAV),手机浏览器/app 都能直接播

(可选)GET http://10.153.47.252:8013/messages/inbox
     → 一个网页版收件箱(手机浏览器打开,带播放按钮)——应急兜底用
```

若队友提供接收接口,手板每条新留言主动 POST:

```
POST <队友给的URL>
Content-Type: multipart/form-data
  audio   = msg_xxx.wav(文件)
  time    = 2026-10-24 19:30:05
  duration= 23.5
  elder   = 手板编号(现在固定 "hand-A",以后做多用户再扩)
```
(字段名/格式都可以按队友后端的习惯改,他要什么样的我们拼什么样的)

## 3b. 新增:家属给老人"回话"的接口(手板已建好,2026-10-24 上线)

老人床头屏上现在有「留言」和「听留言」两个键:**家属听完老人的留言,可以给老人发回一句语音,
老人按「听留言」(或直接说"听留言")就能听到——双向留言闭环**。家属端发回话只需调一个接口:

```
POST http://10.153.47.252:8013/family_message
Body: 裸 PCM(16kHz/16bit/单声道) 或 WAV 都行(≤60 秒)
  - app 用 java/android 原生录音: AudioRecord 16k 单声道 16bit 的裸 PCM 直接 POST 即可
返回: {"ok":true,"id":"fam_20261024_200506","duration":12.3}
```

- 家属发完,老人侧**立刻**能按「听留言」听到(手板按修改时间取最新一条,家属回话自动排最前)。
- 不需要家属端做任何"标记"动作,一条 POST 就完事。
- 若队友后端代转发(家属 app → 后端 → 手板),后端只需原样转 POST 这个接口。
- 老人端播放顺序:最新的排最前;暂时只播最新一条(后续可扩"把没听过的都听一遍")。

## 4. 需要队友逐条回答的问题(回复编号+答案即可)

1. **App 有没有自己的后端服务器?**
   (有 → 请给:接收留言的 POST 接口 URL + 想要的字段格式;没有 → 跳到第 3 题)
2. 有后端的话:**App 怎么被通知有新留言?**(轮询后端/推送/长连接都行,给个说法;顺带说明家属手机在 App 杀掉后还能不能收到)
3. 没后端的话:**能否接受"App 在后台每 30 秒静默轮询手板的 /messages 接口"?**
   前提:家属手机和手板连同一个热点(演示环境就是如此)。
4. **App 跑在什么平台?**(安卓/iOS/鸿蒙?原生还是 Flutter/小程序套壳——影响能不能后台轮询)
5. 有没有**老人↔家属的绑定关系**(登录账号/设备绑定码)?没有的话,演示阶段就先按"单老人→所有家属"广播,后面再加绑定。
6. 最终演示场景里,**家属手机能连哪个网?**(赛方现场热点/自家 4G)——决定走局域网还是必须过公网。
7. 若一定要**公网零操作收听**,需要一台公网可达的服务器:队员有没有学校/公司的服务器或云主机可用?没有的话我们再商量免费云中转方案(如 MQTT 通知+对象存储)。

## 5. 选型速查(给队友决策用)

| 队友的情况 | 接法 | 家属体验 | 联调工作量 |
|---|---|---|---|
| 有后端接口 | 手板每条留言主动 POST | 零操作,可推送通知 | 双方各写少量代码,最正规 |
| 无后端,能做后台轮询 | App 轮询 /messages | 零操作(app 得开着) | App 端一个定时器+一个播放器 |
| 两者都暂时没有 | 网页收件箱兜底 | 要输一次网址 | 零(手板已做) |

**推荐**:第 1 或第 2 行。网页兜底无论如何都会建好,不依赖队友。
