# 硬件后端集成说明（2026-10-24）

硬件 kit 是资料来源，不是第二份运行时。现场只启动仓库自己的
`code/hand_controller/arm_service.py`，端口仍为 8013；kit 里的命令名通过
HTTP 别名兼容，不把 kit 的 `arm_service.py` 复制进来。

## 已接入

- RH56F2：Modbus RTU、RS485、115200-8N1、从站 ID 1/2。
- FC03 读、FC06 单写、FC16 批写，CRC 和响应回显都会校验。
- `code/hand_controller/rh56_register_map.py` 集中保存寄存器和量程。
- `code/hand_controller/rh56_backend.py` 把主脑规范动作映射到手姿态。
- `code/hand_controller/arm_backend_vendor.py` 是 Panthera-HT 的唯一 SDK 接入槽。

## 安全开关

默认完全 mock。真实 RH56 写链路必须同时满足下面三个条件：

```text
MOCK_SERIAL=0
RH56_REGMAP_CONFIRMED=1
rh56_register_map.PROVISIONAL = False
```

`RH56_REGMAP_CONFIRMED=1` 前，必须按照
`docs/10_RH56F2驱动笔记_待核对.md` 对照实际固件手册核对目标、速度、状态和控制寄存器。串口能打开、厂家上位机能动手，都不等于仓库寄存器表已经核对完成。

Panthera SDK 未提供前，`press_sos`、`deliver_medicine`、`sign_coming` 和机械臂归位会明确返回失败；系统不会把日志打印当成动作成功。

## 真手启动前检查

```bash
pip install -r code/requirements-hardware.txt
python tests/run_all.py
python -m tools.hardware_preflight --arm-url http://127.0.0.1:8013
```

`hardware_preflight` 是只读检查：它不会打开串口、发送姿态或写寄存器；
real 模式还要显式带上 `--require-real`，并且寄存器表不能仍标记为占位。

确认 `HAND1_PORT`、`HAND2_PORT`、`HAND1_ID`、`HAND2_ID` 后，再在现场打开真实模式。任何异常先断开 24V，不能在带电状态触碰端子或修改蓝盒 DIP。
