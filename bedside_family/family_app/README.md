# 家属 App(原生安卓,家人留言 v2)

给家属手机装的**原生 APK**:不需要浏览器、不需要访问网页,微信传 APK → 点开装 → 连床头同 WiFi → 打开就用。零第三方依赖,纯 Java 单 Activity + 守护服务,~30KB。

## 功能与行为参数

| 功能 | 行为 | 参数 |
|---|---|---|
| 听 TA 说 | 拉 `GET /messages` → 列表(老人 msg_* + 家属 fam_*) → 点播原声 WAV | 原声不转文字 |
| 我来说 | AudioRecord 16k/16bit/mono 直采 + 手工 WAV 头 → `POST /family_message`(裸 body octet-stream) | 单条 ≤60s |
| 跌倒警报(前台) | 3 秒轮询 `GET /alarms`,见新未确认条 → **全屏红条+警铃循环+震动** | 「知道了」→ `POST /alarms/ack` |
| 跌倒警报(后台) | GuardService 常驻前台服务(dataSync 类型)10 秒轮询 → **系统级高优通知**(sound=alarm+震动+bypassDnd) | START_STICKY |
| 警报历史 | 已确认警报以红卡置顶展示 | — |

轮询双通道设计目标:检测端 POST 落账 → **app 前台 3 秒内响,关着 10 秒内弹系统通知**。

## 网络(4G 场景预留)

`java/com/mocen/caremate/family/Cfg.java`:

```java
LAN_BASE   = "http://10.170.215.251:8013"  // v1.5:仅作初始猜测,失联时自动全段扫描找回(见 MainActivity.subnetScan)
CLOUD_BASE = ""                             // 中转站落地后填这里,填了自动优先走云端 → 4G 全域可用
```

升级为公网版的完整步骤:填 `CLOUD_BASE` → 重跑 `build_app.py` → 同签名覆盖安装,无需卸载。

## 构建

```powershell
python family_app/build_app.py
# 产出 family_app_v2.0.apk,自动同步桌面(家人留言v11.apk)
```

> 版本沿革:v1.1(versionCode 2)首开即闪退(MainActivity 警报条对未挂载 View 取 LayoutParams 的 NPE,**javac/CI 抓不到运行期 NPE**)→ v1.2(3)删冗余行修复,真机验证前台警报闭环 PASS;但熄屏/退后台无提醒(Android 13+ 通知权限无权限时 `nm.notify()` 静默丢弃 + 无电池优化白名单 + 无锁屏弹出能力)→ v1.3(4)=后台提醒修复:权限提醒条+电池白名单引导+锁屏全屏意图+API29+ 显式 dataSync 前台服务类型;真机四轮熄屏仍无响应(用户已开通知/省电/自启动/WLAN 休眠全套开关)→ **v1.4(5)=闹钟级拉活链:`setAlarmClock` 每 10s 挂一拍系统精确闹钟(内核计时,无需特殊权限),进程被 ROM 杀掉也会被 PaceReceiver 重新拉起——闹钟/电话类 App 的标准存活方式;另加"守护自检行"(lastPoll 轮询年龄+通知/后台权限一览),熄屏测试后开 App 一瞄即分清"服务死了"还是"通知被丢"**。同签名升级覆盖安装。桌面交付别名:v2=broken v1.1,v3=v1.2,v4=v1.3,v5=v1.4,**v6=v1.5**。

**v1.5(6)=网络自愈**:手机热点重启会随机换网段(实测 10.153.47.x → 10.170.215.x,全队设备一夜失联一次),App 里写死的板子地址随之作废 → 静态地址连不上时自动枚举本机所有 IPv4 网段、24 线程并行扫各 /24 的 8013 端口 + `/status` 验身(单网段最坏 ~4s,20s 冷却防每轮全扫),命中即回连并存 SharedPreferences;前台 3s 轮询与后台 GuardService(主力)都接了该路径——**只要 App 和板子在同一个网里,板子换任何 IP 都自己找回来,不再需要重新打包**。LAN_BASE 从"写死地址"降级为"初始猜测"。**v1.6(7)=「听 TA 说」列表撤掉已确认警报历史小卡**。**v1.7(8)=修播放竞态炸错**(全部播放器操作串行化)。**v1.8(9)=先下载后播放+全程按钮反馈**:板子 WiFi 链路抖(实测单请求 0.3~47s),MediaPlayer 网络流卡住时用户毫无感知——点按瞬间按钮变「下载中…」,拿全文件(超时 12s)本地毫秒级起播,按钮换「■ 停止播放」,播完/失败复原;同一条再点=停止;试听同通道。**v1.9(10)=预下载秒播**:列表每次刷新即后台缓存最新 12 条到本地(失败静默,下轮再续),点播命中缓存毫秒级出声,未命中才现下;换播另一条时旧条按钮自动复原。

**v2.0(11)=稳定性与漏报修复**(2026-10-25,在 v1.9 预下载秒播的基础上;Android 14 模拟器 + 假床头逐项实测,**真机待装机验证**,验证后再记 CHANGELOG):

| # | v1.9 及以前的问题 | v2.0 |
|---|---|---|
| 1 | 回到 App 时在**主线程**拉警报;连不上时连网段扫描也在主线程,界面卡死最长 ~4s(有 ANR 风险) | 网络一律走后台单线程(不并发、不堆积),主线程只动界面 |
| 2 | 警报轮询每 3 秒把留言列表整个重建:闪一下、滚动位置跳回顶部、"有 N 条新留言"一闪就没 | 警报轮询不碰列表;列表内容没变就不重建 |
| 3 | App 内警铃走**媒体音量**,媒体音量为 0 时全屏红条但没声音 | 改走闹钟音量通道(`USAGE_ALARM`),找不到闹钟铃声退到来电/通知铃声 |
| 4 | 别的家人点了「知道了」,这台手机还一直响 | 轮询发现已确认 → 停铃、收红条、收系统通知 |
| 5 | 「知道了」只确认一条;床头上更早的未确认警报(含测试警报)接着一条条再响;系统通知不收回 | 一次确认床头上全部未确认警报,并收回通知;确认没送到会提示 |
| 6 | App 开着时守护服务也弹系统警报通知,两种铃声叠响 | 前台时守护服务不弹;退到后台没确认的照常弹 |
| 7 | 手机开着代理 / 翻墙软件时,连床头的请求全进了代理 → 整台手机连不上床头(听留言也放不出来) | 局域网地址直连不走系统代理(含留言下载 / 预下载) |
| 8 | 录音:麦克风被占用时直接崩;松手瞬间录音线程还在读已释放的设备;**授权麦克风后自动开录、一直录满 60 秒** | 打不开就提示;先等录音线程退出再释放;授权后提示"再按住说话" |
| 9 | 顶部连接状态文字颜色少了 alpha 字节,**整行透明看不见**;录音页计时 / 提示贴左边 | 修正颜色;居中;录音时计时实时跳 |
| 10 | 关掉页面后 3 秒轮询还在跑;热点换网段后守护服务每轮先白等写死地址 2.5 秒 | 页面不可见就停;守护服务先试上次找到的地址 |

模拟器实测项:启动无崩溃;连接状态可见;代理开启下仍连上床头;新警报 3 秒内红条 + 闹钟通道响铃且前台无重复通知;别处确认后停铃、下一条照常响;两条未确认一次确认、不再重响;后台 ~8 秒弹系统警报通知、别处确认后 ~8 秒收回;播放(下载中… → ■ 停止播放 → 播完复原);录音计时、发送到床头;授权麦克风后不自动开录。

> ⚠ 构建注意:`build_app.py` 的 `SRC` 指向构建者本机的源码目录。用仓库版本构建前,先把仓库 `family_app/android/` 同步过去(或把 `SRC` 改成仓库路径),否则会用旧源码打包。必须用原来的稳定签名(`caremate_stable.ks`)打包,才能覆盖安装。
