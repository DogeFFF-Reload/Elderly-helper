# CareMate 现场执行清单（按当前分工）

更新：2026-10-24。旧版 Modbus、PROVISIONAL 开关、SDK 占位和能量阈值流程已撤下。此清单供到现场以后使用；当前开发没有连接硬件，也不要求用户补采数据。

## P0：全队先确定演示版本

1. 获取 main 的最终代码，确认大家使用同一提交；本轮已整合 T5AI 屏幕和语音分支。
2. 确定演示主机、摄像头来源和最终网络。电脑摄像头与 iPhone 是两条输入路径，分别记录验收结果。
3. 先用 START_FULL_VISION_DEMO.bat 回放已有骨架，确认软件主线与大屏可用。这一步不打开摄像头或执行端。
4. 明确现场主程序与独立模拟主程序的区别：新实时模拟入口只连接自己创建的本机服务，不会控制现场机械臂。

## P1：用户负责视觉，硬件队友负责设备

用户只需在有条件时固定镜头，让肩部和髋部入镜，按电脑屏幕提示做普通活动；不用操作串口、寄存器或机械臂。

- 只观察电脑摄像头：START_PC_CAMERA.bat。
- 电脑实时骨架接完整模拟流程：START_LIVE_VISION_DEMO.bat。
- iPhone 只观察或接完整模拟流程：见 docs/26 第4、10节，使用 App 显示的完整 MJPEG 地址。
- 出错时把结果 ZIP、发生的动作和屏幕现象交回；不用自行改阈值，不把无人或关键点缺失叫作跌倒。

硬件队友确认以下事项并提供结果，软件侧不远程代为调用设备：

- 仓库 arm_service 的版本、后端模式、端口和日志；不用 kit 服务。
- 机械臂实际工作点示教、递药/还药/SOS/举牌动作、急停和断电保护；小角度自检文件不能当正式工作点。
- RH56F2 的官方固件寄存器地址、双手接线与 ID；VERIFIED=False 时不启用真实写入。
- T5AI 本机 caremate_local.h、按钮/语音请求、动作真实完成情况；在线灯只说明 HTTP 可达。
- 主脑与床头屏同时使用时，资源锁、急停和动作争用的表现。
- 喇叭、麦克风、屏幕位置，以及现场声音是否听得清、真人语音能否识别。
- 两块 X5 的模型、性能、网络、时区和重启恢复。新手机配置改填 PHONE_STREAM_URL，删除 PHONE_URL / PHONE_ARGS。

硬件具体上电与示教以 docs/开机步骤.md、docs/硬件安全简报.md 和硬件负责人确认为准；此页不代替厂家指导。

## P2：视觉效果与上台准备

1. 有合适、安全且明确标注的素材后，评估坐下、弯腰、遮挡、倒地等场景；当前不要求用户做跌倒动作或重复采集。
2. 如果展台展示猜拳，再验收真人石头/剪刀/布的一整局。
3. 按 docs/演示脚本_3分钟.md 彩排至少三轮，填写每段时间，准备药盒/举牌。
4. 最终演示稳定后录现场完整备份，检查可以离线打开，再由全队确定冻结提交并打 demo-final。软件模拟备用 MP4 已准备，不能替代现场录像；当前不把自动化测试次数当彩排次数。
