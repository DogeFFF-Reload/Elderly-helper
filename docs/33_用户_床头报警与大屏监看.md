# 床头自动报警和外接大屏：你需要做什么

两件事的软件已经接在一起：iPhone提供画面；运行视觉程序的设备识别疑似跌倒；床头服务登记警报；家属App读取警报并提醒。大屏用浏览器显示同一份画面和骨架。

推荐把视觉程序放到床头的 **X5计算板** 上。能否在这块板子上顺利运行姿态模型、实际速度是否够用，仍需队友在现场按第34份文档检查。现有床头小屏幕或微控制器不能直接代替X5运行这套Python视觉程序。

## 在Windows上直接打开CareMate直播

仓库根目录新增 `START_LIVE_MONITOR.bat`，双击后按提示输入手机摄像头App的HTTP地址、账号和密码，浏览器会自动打开 `http://127.0.0.1:8015/`。可以从任何目录启动，无需自行设置Python模块路径。登录信息使用已经在原摄像头网页验证成功的那组；密码输入时不显示字符，也不保存到配置或结果。没有登录要求时，账号处输入 `-`。

此入口固定为“仅观察”，持续运行直到在命令窗口按Ctrl+C或发生输入故障，不发送家属报警。请保持命令窗口开启。关闭浏览器页面不会停止后台识别。

如果账号密码验证失败，网页会保留“摄像头连接失败”和具体中文提示，启动窗口不会立刻消失；回到窗口按回车即可重新输入，输入 `Q` 才结束。程序支持常见的 Basic 和 Digest HTTP 登录认证。你不需要把密码发到聊天里。

这个网址是我们自己的CareMate监看页；手机App提供的 `http://手机IP:8081/` 则是第三方摄像头页。CareMate只显示当前画面和骨架，没有暂停、进度条、录像和回放入口。画面中断时遮住旧画面，返回网页时直接获取当前画面，不补播离开期间的内容。

程序可从摄像头首页中明确的、同一地址下的图片引用找到MJPEG直播流；不执行网页脚本或猜测接口。如果提示“没找到可读的MJPEG直播流”，请在原摄像头网页的实际画面上右键，选择“复制图片地址”，重新启动后粘贴这个地址。若浏览器没有这个选项，保留提示交给开发者检查；当前入口不接RTSP或网页录像播放器。

固定iPhone并在App中选择单个后置摄像头；若CareMate中图像仍横着，先调整手机App的输出方向，再开始识别测试。网页上的旋转操作未必会改变实际输入方向。先以画面朝向正确、人物肩部和髋部完整可见为准。

## 显示器接在哪里

**本次就用“显示器接Windows电脑”这条方案。** 你和队友不用再挑选：让电脑负责浏览器和大屏，iPhone负责拍摄。识别优先在X5运行，若它的模型环境未通过自检，再由队友使用同一程序的Windows备用方法。

| 接法 | 画面怎么到显示器 | 你要做什么 |
|---|---|---|
| 显示器接Windows电脑，本次采用 | 电脑浏览器访问监看网页，通常由X5转发画面 | Win+P选“扩展”，把浏览器窗口拖到外接显示器，点“全屏显示”或按F11 |
| 显示器直接接X5，备用了解即可 | X5本机浏览器打开同一个监看网页 | 需硬件队友先确认X5的显示接口、线材、桌面系统和浏览器 |

两种接法都由X5识别和登记报警。第一种接法中的电脑只负责显示，关闭监看网页不会停止X5上的识别。

**不用把iPhone用线插进显示器。** iPhone继续使用此前已连通的摄像头App提供MJPEG视频。X5、iPhone和用于监看的电脑要能在同一网络互相访问。

如果现场X5的模型环境暂时跑不通，可以先在Windows电脑运行同一视觉入口，发送到床头服务并在外接屏监看。此时识别在电脑上进行，不能称为“已经移到床头设备”。第34份文档包含这个临时演示方法。

## 到现场以后，你只负责这四步

1. 固定iPhone，保持摄像头App在前台，关闭会让画面停止的锁屏设置。让肩部、髋部和尽可能完整的身体进入画面。尽量沿用之前测试的镜头和机位。
2. 把手机App当前显示的视频流地址交给队友，由他填配置和启动程序。手机换网络后地址可能变化。
3. 让队友给你一个可直接打开的监看网址，在Windows浏览器打开。视觉在X5上运行时通常是 `http://X5的实际IP:8015/`；若采用Windows备用运行，则是 `http://127.0.0.1:8015/`。你不用自行判断，由队友给出正确的那一个。按Win+P选“扩展”，把浏览器窗口拖到外接屏，再点“全屏显示”或按F11。
4. 先看清右上角“仅观察”。正常站立、走动、缓慢坐下再站起，确认画面持续更新、能画出骨架。队友持有家属手机，确认一条测试警报成功后，才由他切换“正式报警”。

这些检查不需要你真的摔倒。切换成正式模式后，规则确认疑似跌倒会自动发出事件，无需你再按发送按钮。

## 画面上的字分别是什么意思

| 提示 | 实际含义 |
|---|---|
| 仅观察 · 不发送报警 | 看画面和识别，不访问床头报警接口 |
| 无扰测试 · 不建立警报 | 检查接口格式，不应因此触发家属手机警报 |
| 正式报警 · 自动上报 | 规则确认疑似跌倒后自动上报 |
| 疑似倒地，正在确认 | 还在判断，不等于已经通知家属 |
| 床头已登记警报 | 床头返回接收回执；手机是否收到仍要现场确认 |
| 画面已中断 / 监看连接已断开 | 当前无法持续看到新结果，需要队友检查输入、网络或服务 |

网页本身不播放报警声。家属App的声音、震动和通知由装有队友App的 **Android家属手机** 发出；你的iPhone在这里负责拍摄。这个接口不会自动拨打120。

画面在内存中处理并传到监看浏览器，不保存录像，也不随报警接口发给家属App。识别程序退出时保存结果摘要和事件记录，供Debug使用。

## 演示前还需要队友确认

- X5上的模型能加载；监看页实际处理帧率和人物骨架稳定，长时间运行没有明显卡顿。
- 摄像头App在当前网络能持续提供画面；摄像头被遮住、App退出或网络断开时能看见中断提示。
- 家属手机在前台和退到后台时各完成一次受控接口测试，记录是否响铃、震动及延迟。床头回执不能代替这一步。
- 同一个场景只运行一个跌倒检测入口，避免电脑和X5同时识别、各发一条警报。

最终应由队友给你三个明确结果：**监看网址、真实运行设备、家属手机测试结果**。你不需要自行接机械手、刷固件或修改床头硬件服务。
