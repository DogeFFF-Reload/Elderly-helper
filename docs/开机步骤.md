# 开机步骤（软件同学一页纸）

> X5-A 视觉；X5-B 主脑 `:8000` + 执行端 `:8013` + 屏/语音（README §10.9）。`python -m ...` 在 `code/` 下执行（X5 用仓库 `.venv/bin/python`；**真臂例外**，用装了 SDK 的 `~/panthera_venv/bin/python`，见 §1.6）。拿不准的不要猜，按硬件同学确认后再补。上电前全员看过《硬件安全简报》（`docs/硬件安全简报.md`）。

## 1. 开机前 30 秒安全检查

- [ ] **急停**：知道位置和按法，按钮无遮挡。位置【待硬件确认】。
- [ ] **臂周围无人**：臂和手#1/#2 够得着的范围内无人、无杂物（臂伸直约 0.6 m）。臂停在 **rest**（零位 = 收拢折叠的姿态）；**不要回零 / 置零**（零点存在电机里，`0_robot_set_zero.py` 一跑错，限位整体偏移）。
- [ ] **24V/5A 电源**：标注 24V/5A，插头/端子插紧；开关位置【待硬件确认】。
- [ ] **USB-RS485**：插在 X5-B，接头插到底/拧紧；USB 口【待硬件确认】。
- [ ] **摄像头**：接 X5-A，镜头无遮挡；`CAMERA_INDEX`【待确认】（`v4l2-ctl --list-devices`，默认 0）。
- [ ] **显示器**：接 X5-B，通电、输入源对。
- [ ] **喇叭/麦克风**：接 X5-B 还是床头盒【待硬件确认】（映射写 X5-B，README §9 未定）；X5-B 的 USB 口够不够【待硬件确认】。
- [ ] **网络**：同一网络；`deploy/x5.env` 的 `MASTER_HOST` 为 X5-B 当前 IP，现场 IP【待确认】（示例 `192.168.1.20`）。
- [ ] **ASR**：麦克风接 X5-B 时 `deploy/x5.env` 设 `WITH_ASR=1`，否则不生成 `caremate-asr`。

## 1.5 手第一次上电（详见 README §10.13）

1. 先看手上型号：`RH56F2-E2…`（RS485）才能用现在的驱动；`E4…` 是 CAN FD 版，先别接。**这只手不用烧录。**
2. 上 24V 后：`MOCK_SERIAL=0 HAND2_PORT=<COM 口> HAND2_ID=1 python -m hand_controller.arm_service --probe` → 只读一次实际角度，读到 6 个数才往下走。
3. `rh56_register_map.VERIFIED` 没改成 True 之前，真机只读，动作一律被拒——这是故意的。

## 1.6 真臂（Panthera-HT，X5-B，详见 README §10.14）

`deploy/start.sh arm` 现在还起不了真臂（用的是仓库 `.venv`，没有 SDK），先手动起；`caremate-arm` 若已启用，先 `sudo systemctl stop caremate-arm`，否则抢 `:8013`。

```bash
ssh rdk-x5                                   # 笔记本直连网线，X5 = 192.168.127.10
sudo date -u -s "<笔记本的 UTC 时间>"          # X5 没电池，每次开机时钟都回到旧时间
cd ~/Elderly-helper/code
~/panthera_venv/bin/python -m hand_controller.arm_backend --check-fk     # 只算数，要看到"一致"
ARM_BACKEND=panthera ~/panthera_venv/bin/python -m hand_controller.arm_service --probe   # 只读一次关节角
ARM_BACKEND=panthera ARM_EFFECTOR=gripper ~/panthera_venv/bin/python -m hand_controller.arm_service --host 0.0.0.0
```

- 点位还没示教时，正式动作会被拒；先用小角度自检文件验链路：起服务时前面加 `ARM_SKILLS_FILE=hand_controller/arm_selftest.json`（README §10.14 第 5 步）。
- 末端现在定的是 Panthera 夹爪（`ARM_EFFECTOR=gripper`，2026-10-24）；换手#1 时改成 `hand1`。
- 起服务后要看到“臂：panthera，末端 gripper，可以动”；没示教的点位会列出来，用到它们的动作会被拒（422），这是故意的。
- “另一个程序正在控制机械臂”：SDK 单实例锁，先关掉示教工具 / SDK 示例脚本。
- “电机层越界锁定”：关节转出了范围，全部电机已阻尼。断开前扶住臂，对着零位标记把关节推回，再重启 `arm_service`。

## 2. 上电顺序

1. **先 X5-B（主脑）**：主脑和执行端都在这块；先起主脑，X5-A 的视觉才有人收，大屏也在等 `:8000`（最多 60 秒）。
2. **登录 X5-B 桌面**，等大屏出现 `http://127.0.0.1:8000/ui/monitor`。
3. **再开 X5-A（视觉）**，vision 是 systemd，开机即起；猜拳时再手动 `rps`。

| 板 | 开机即起（systemd） | 桌面登录后自启 |
|---|---|---|
| X5-A | `caremate-vision` | 无 |
| X5-B | `caremate-arm`、`caremate-master` | `caremate-tts`、`caremate-kiosk`；`WITH_ASR=1` 加 `caremate-asr` |

- `rps` 不自启：X5-A `bash deploy/start.sh rps`。
- **X5-B 停在登录界面：只有 master/arm 在跑，大屏和语音都不起**。

## 3. 怎么确认起来了

在任意机器上（`<X5-B 地址>` 换实际 IP）：

```bash
cd code
python -m tools.preflight --server http://<X5-B 地址>:8000 --wait 60
```

| 项目 | ❌ / ⚠️ 时 | 第一步（照 preflight 提示） |
|---|---|---|
| 状态机 | ⚠️ 不在“空闲” | 操作台点“重置” |
| 急停 | ❌ 软件急停未解除 | 确认臂周围安全 → 操作台右上角“解除急停” |
| 时区 | ⚠️ 本机不是 UTC+8 | X5 上 `sudo timedatectl set-timezone Asia/Shanghai` 后重启主脑；夜间段用操作台开关 |
| 执行端 | ❌ 连不上 `:8013`；⚠️ 动作被拒 | X5-B `bash deploy/start.sh arm`（真臂按 §1.6 手动起）；地址改 `CAREMATE_ARM_URL`；被拒的原因操作台日志里有（没示教、禁区、409 正忙），找硬件 |
| 喇叭 | ❌ 无 `tts_player`；⚠️ 只有“未标名” | X5-B `bash deploy/start.sh tts`；更新 `voice/bus_client.py` 后重启；兜底大屏播报 |
| 麦克风 | ⚠️ 无 `asr_bridge` 且没听到 | X5-B `bash deploy/start.sh asr`；兜底操作台输入框 |
| 视觉 | ⚠️ 3 秒无骨架 | X5-A `bash deploy/start.sh vision`；Plan B 见 §7 |
| 床头盒 | ⚠️ 无心跳/超 3 秒 | 查固件每 0.5 秒 `GET /api/box?id=box1`；兜底操作台绿键 |
| LLM | ⚠️ 没配全/最近出错 | `config.local.json` 填 `llm_base_url`/`llm_model`，或切 `scripted` |
| 演示参数 | ⚠️ 非默认 | 确认改动；重启主脑恢复默认 |

- 无 ❌ 退出 0，有 ❌ 退出 1，主脑连不上 2；`--wait 60` 只等 ❌，不等 ⚠️。
- 主脑连不上 → X5-B `bash deploy/start.sh master`；提示无 `/api/nodes` → `git pull` 后重启主脑。
- 床头盒协议是草案（README §10.6），固件是否已实现心跳【待硬件确认】。

## 4. 单个服务没起来

`<服务>` 是服务名去掉 `caremate-` 前缀：`vision`/`master`/`arm`/`tts`/`kiosk`/`asr`。例：master 的状态 `sudo systemctl status caremate-master`、手动起 `bash deploy/start.sh master`、日志 `journalctl -u caremate-master -f`。

| 类型 | 服务名（板） | 手动起 / 日志 |
|---|---|---|
| systemd（开机即起，挂 2 秒重启） | `caremate-vision`（A）、`caremate-master`（B）、`caremate-arm`（B） | `bash deploy/start.sh <服务>`；`journalctl -u caremate-<服务> -f` |
| 桌面登录后自启 | `caremate-tts`、`caremate-kiosk`、`caremate-asr`（B，仅 `WITH_ASR=1`） | `bash deploy/start.sh <服务>`；`tail -f ~/caremate-<服务>.log` |

- systemd 已启用时先 `sudo systemctl stop caremate-<服务>` 再手动起，否则抢 `:8000`/`:8013`；调完 `sudo systemctl start caremate-<服务>` 交回。
- 桌面自启要有人登录桌面；`start.sh` 缺 `deploy/x5.env` 会报错，先 `cp deploy/x5.env.example deploy/x5.env` 再改 `MASTER_HOST`。

## 5. 笔记本单机彩排（没有 X5）

```powershell
powershell -ExecutionPolicy Bypass -File deploy\start_laptop.ps1
powershell -ExecutionPolicy Bypass -File deploy\start_laptop.ps1 -Vision camera -Asr vosk
```

默认 master + arm mock + TTS 各一窗，并打开操作台/大屏；`-Vision camera` 加摄像头预览，`-Asr vosk` 加 Vosk，`-NoTts` 不起 TTS。

## 6. 开演前最后 3 步

1. **preflight 无 ❌**：`python -m tools.preflight --server http://<X5-B>:8000 --wait 60`。
2. **操作台点“重置”**：`http://<X5-B>:8000/ui/console`。
3. **联调冒烟**：`python -m demo_driver --server http://<X5-B>:8000`。

> **不要加 `--local`**：它是进程内假时钟、不连服务，只验代码，验不了 X5、臂、喇叭、视觉。要人控节奏加 `--pause`。冒烟会真动臂、发通知，正常跑完停在救援段，开演前再点“重置”（健康记录保留）；退出码非 0 = 有步骤没过，回 §3/§4 查。

## 7. Plan B 速查

视觉正常用 `--camera`；不稳时按 README §11.4 顺序换，命令前缀均为 `python -m vision.fall_bridge`：

| 哪个坏了 | 换成什么 |
|---|---|
| 实拍跌倒判定不稳 | `--video falls/fall_01.mp4` |
| 视频也没有 | `--keypoints falls/fall_01.jsonl` |
| 摄像头/模型都没有 | `--synthetic fall` |
| 视觉全不行 | 操作台“触发摔倒”按钮 |
| 麦克风/ASR | 操作台“让老人说”输入框 |
| 喇叭/TTS | 大屏右上角“大屏播报” |
| 执行端/机械臂 | 手走 mock（`arm_service` 不接硬件）+ 大屏“床边执行端”动画照常演；只有臂坏：`ARM_BACKEND=mock` 重起 `arm_service`，手照常用真的 |
| 臂动作异常、有人靠近 | 操作台 `Esc` 软件急停（臂当场停住保持、双手停住，之后不再收指令，保命链照常）；仍在动 → 物理急停【位置待硬件确认】；最后一道：断臂的 24V |
| 床头盒 | 操作台“绿键”按钮 |
| LLM/网络 | 自动回落 `scripted`；必要时 `config.local.json` 的 `llm_mode` 改 `scripted` 并重启主脑 |

## 8. 关机顺序

1. **停 `arm_service`**（Ctrl+C / `sudo systemctl stop caremate-arm`）：它会先慢速回 rest、再转阻尼，看着臂收拢停稳（回的路上再按一次 Ctrl+C 立刻停住）。窗口里出现“不在 rest”时扶住臂：阻尼挡不住重力，J2/J3 会慢慢往下沉。
2. 断开臂和手的 24V，再关两块 X5【先关哪块待硬件确认】。
3. 出事时不按这个顺序：先 `Esc`（臂停住保持），仍在动就拍物理急停 / 断 24V——**断电后臂会失力落下**，人先离开臂下方。
