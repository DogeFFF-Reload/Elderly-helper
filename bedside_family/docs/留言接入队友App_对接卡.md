# 留言功能接入摔倒警报 App —— 对接卡 v2(发给队友)

> 目标效果:**家属打开 app 就能用——不连热点、不输网址、不访问任何网页。**
> 结论:摔倒警报和老人留言走同一条"手板↔中转站↔手机"通道,手板侧接口全部就绪,
> 只差你一个"中转站"(后端)或者告诉我们用哪个云。

---

## 0. 为什么必须要个中转站(1 段话讲清)

手板在机器人旁边的**内网**里(10.153.47.252 是局域网 IP),全世界都进不来它;
但手板**能主动出网**(已验证:它能调通公网 LLM 网关)。
所以"打开 app 就能用"的唯一路径是:

```
老人留言 ──手板主动PUSH──▶ 中转站(你们后端/云) ◀──app打开就从这拉── 家属手机
家属回话 ──app发给中转站──▶ 中转站 ◀──手板每5秒主动来拉── 手板→老人听到
```

手板方向全是我们来写;app 只需要跟**你们自己的中转站**打交道(它本来就要为摔倒报警这么干)。

## 1. 手板侧已就绪(不用你开发)

- 老人床头屏「留言」键(点一下开录、再点一下发送,≤60秒)+「听留言」键(播家属回话)+ 语音"我要留言/听留言"同样触发。留言是**原声语音**,不转文字。
- 手板每条新留言**自动 PUSH** 到你给的 URL(钩子已实现):
  ```text
  配置 FAMILY_PUSH_URL=<你的接收URL> 后自动 POST multipart/form-data:
    audio    = msg_xxx.wav (audio/wav 文件)
    time     = 2026-10-24 19:30:05
    duration = 23.5
    elder    = hand-A
  ```
- 手板定时**拉取**家属回话(钩子已实现,配置 FAMILY_PULL_URL 后每 5 秒):
  ```text
  GET {FAMILY_PULL_URL}?elder=hand-A&after=<上次已取id>
  → {"ok":true,"replies":[{"id":"...","pcm_b64":"<16k/16bit/mono PCM 的 base64>"}
                           或 {"id":"...","wav_url":"https://.../x.wav"}]}
  replies 按时间升序返回即可,没新的 replies 给空数组。
  (可加请求头 X-CareMate-Token 做简单鉴权,FAMILY_PULL_TOKEN 配置即启用)
  ```
- 演示兜底(不影响主线):手板自带网页收件箱 http://10.153.47.252:8013/messages/inbox,仅限同热点调试时看。

## 2. app 侧要做的事(很少)

1. **收**:app 从你们后端拉"手板推上来的留言列表",点开播放(WAV 标准 16k/16bit/单声道,任何播放器都行)。新留言提醒走你们摔倒报警的推送通道,一样的东西再发一次。
2. **回**:app 里加个"按住说话",用 **AudioRecord 录 PCM(16000Hz/16bit/单声道)**上传后端(后端转存即可,不用转格式);或者 app 直连手板 POST 也行(演示时手机在手板热点下才可用)。
3. **摔倒警报**:你原来的功能,不动。它跟留言共用同一条推送链路。

**唯一要小心的坑:录音必须 16k/16bit/单声道 PCM。安卓 MediaRecorder 默认出的 AAC/m4a 不能用。**
(iOS AVAudioRecorder 设置 AVFormatIDKey=kAudioFormatLinearPCM、16000、单声道、16bit 即可。)

## 3. 中转站方案二选一

| 方案 | 谁干活 | 家属体验 | 适合 |
|---|---|---|---|
| **A. 你们的后端** | 你们后端加 2 个小接口:①收手板 POST 的留言(mp3都行只要能存)②给手板拉回话的 JSON(上面格式) | 打开 app 即有,可推送 | 你们本来就要为摔倒报警建后端,**推荐** |
| **B. 我们上免费云** | 用户侧全包:用腾讯云 CloudBase/LeanCloud 免费档做中转,手板直推直拉;app 只需调它的 REST(给个文档) | 打开 app 即有 | 你们不想碰后端/没有服务器 |

A/B 之外没有第三种能"打开即用"的路(手机 4G 网络里 app 够不着手板内网,这是物理限制)。

## 5. 跌倒警报契约(v5.7,2026-10-24 新增)

检测端(你们的摄像头跌倒识别)→ 家属手机警报,一条 HTTP 就接上:

| 项 | 内容 |
|---|---|
| 上报 | POST http://10.153.47.252:8013/fall_alarm |
| body(推荐) | {"kind":"fall","src":"cam-A","conf":0.9,"event_id":"唯一事件号"} |
| event_id | **强烈建议**:同号重发/网络重试服务端自动去重,只响一次(返回 dedup:true + 原条目 id) |
| 空 body | 也收(兼容旧姿势) |
| 成功返回 | {"ok":true,"dedup":false,"id":"al_..._毫秒","time":...,"kind":...,"acked":false};ok=true=床头已落账 |
| 手机侧 | 拉模式:app 前台 3s 内全屏红条+警铃+震动;关着由守护服务 10s 内系统通知;「知道了」→ POST /alarms/ack {"id":..} |
| 无扰测试 | POST /fall_alarm body {"dry":true} → 只回执({"ok":true,"dry":true,"ver":"5.7",...}),不落账、手机不响 |
| 健康检查 | GET /fall_alarm → {"ok":true,"service":"arm_service","ver":"5.7",...} 无任何副作用 |
| 警报列表 | GET /alarms → {"ok":true,"alarms":[...]} 新在前,50 条(含 acked);id 格式 l_日期_时分秒_毫秒(同秒必不撞号) |
| 版本 | 手板服务 v5.7(alarms.json 掉电恢复,id 毫秒化,v5.6 兼容) |
