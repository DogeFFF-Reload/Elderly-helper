## 已知（高置信）

- 通信：RS485 / RS232 / CAN，默认 **RS485, 115200, 8N1, Modbus RTU**
- 自由度：6（单手 ∀指屈伸+?），小体积灵巧手
- 供电：**24V DC，建议 ≥5A 独立电源**
- 上位机：官方 PC 工具可单机调试；本仓库使用轻量自带 Modbus 帧实现，现场不依赖 `pymodbus`
- 姿态控制思路：写任务寄存器=目标关节角；读回=当前角/电流/温度/错误码

## 现场实证档案（2026-10-24，Day2）

- ✅ **手动操控真手打通**：笔记本 + 蓝盒（COM-USB-CANFD-01）+ `arm_service`（MOCK_SERIAL=0）真手动了
  → **结论：Modbus RTU 帧经蓝盒对 RH56 直通有效**——驱动通信层**不用重写 CAN 帧**，
  "换血协议"任务降级为"备用方案"，上层 poses/词表/API 全不动（原计划保险继续有效）
- ✅ 官方口径佐证（Inspire RH56H1 系列）：**控制接口 = RS485 + CANFD 双支持** → 蓝 65 盒只要进了
  RS485 模式就是正路
- ⚠️ **电流警示再落地**：官方 RH56H1 峰值 **5A@24V**（静息仅 160mA）→ 手上 24V/3A 砖
  在满握尖峰时可能拉跨（掉电/重启）——赛方借 **24V/5A** 的请求维持有效；演示中避免
  "六指满力同时长握"，姿态全用限力档

## 驱动设计（已实现于 code/hand_controller/）

```
rh56_register_map.py   ← 唯一需要现场修改的文件（所有魔数在这）
rh56f2_driver.py       ← Modbus RTU 封装：FC03/FC06/FC16、pose/status/close
poses.py               ← 姿态库：rock/paper/scissors/ok/thumbs_up/wave/fingers1..5
arm_service.py         ← HTTP 服务（默认 MOCK_SERIAL=1）：
                          POST /pose/{name}  兼容验收路径
                          POST /pose?name=... 主脑规范路径
                          POST /handover_med | /handover_item   （mock/后端入口）
                          POST /reset                         （mock/后端入口）
                          GET  /status
```
