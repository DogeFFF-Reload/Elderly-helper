# 现场验收：人出现倒地姿态 → 系统识别 → 床头登记 → 家属手机提醒

这次先固定一种方案：**Windows电脑运行视觉，iPhone提供摄像头画面，床头X5接收警报，队友的Android手机运行家属App。** 先验证这条完整链路，再考虑视觉移到X5和外接大屏，避免现场同时排查多个新变量。

已经完成的离线检查：合成快速倒地、缓慢倒地都能触发规则，通过实际接收端纯逻辑的HTTP接口登记，再由模拟家属客户端读取同一报警并确认；普通坐下不报警。该检查没有打开摄像头，没有访问真实床头，也没有让任何手机响铃。它不能代替下面的真机验收。

## 先准备环境

| 谁负责 | 必须具备 |
|---|---|
| 你 | Windows电脑、当前项目目录及项目`.venv`；电脑接电、测试中不睡眠 |
| 你 | iPhone已有可用的MJPEG摄像头App，画面地址包含端口和完整路径；手机固定、App前台、测试中不锁屏 |
| 队友 | 床头X5服务在线，兼容5.7及更新契约；队友回执报告已部署5.7.1 |
| 队友 | **一台Android家属手机**装队友App；你的iPhone在本轮负责拍摄，不能运行这个APK |
| 一起 | 电脑、iPhone、床头X5、安卓手机连接同一局域网，避免访客网络/客户端隔离 |
| 队友 | App连接的床头地址与命令一致，目前代码默认`http://10.153.47.252:8013`；若IP变化，先修正App配置与命令 |

当前App源码的`CLOUD_BASE`为空，默认走上述局域网地址；本轮不要把家属手机切到仅4G后当作远程通知验收。App前台轮询代码约3秒，后台守护设计约10秒，实际延迟须实测。

**家属手机先把App留在前台，开好通知和声音。** 队友最新回执中v1.2前台曾成功，v1.2/v1.3熄屏后台失败四轮，新v1.4待装机复测。前台与后台要分别记结果。

## 第0步：打开PowerShell，检查视觉环境

以下命令在你的Windows电脑运行。先复制这一段：

```powershell
Set-Location -LiteralPath 'D:\Projects\AI_Workfile\Codex\repo-elderly-helper'
$caremateFamily = 'http://10.153.47.252:8013'
& .\.venv\Scripts\python.exe -X utf8 .\run_bedside_vision.py --check-runtime
```

这条只用内存空白图检查模型，不打开摄像头、不联网发送报警。看到“姿态模型空白图自检通过”再继续。不要改用系统的`D:\python\python.exe`来启动摄像头，它不一定装有项目视觉依赖。

如果缺`.venv`或模型，让队友先按第34份文档准备环境；不要一边真实报警一边安装依赖。

## 第1步：无扰检查床头，再确认iPhone骨架可用

先运行：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\run_family_alarm.py --check-link --mode dry --family $caremateFamily
```

它不打开摄像头，不建立真实警报。看到“健康检查和dry回执通过”再继续。失败就把打印的结果路径给队友，先修床头地址、服务版本或网络。

再粘贴下面这段，在输入提示出现时粘贴iPhone摄像头App上的完整视频流地址：

```powershell
$caremateStream = Read-Host '请粘贴 iPhone App 上已经能用的完整 MJPEG 视频地址'
& .\.venv\Scripts\python.exe -X utf8 .\run_family_alarm.py --phone-stream $caremateStream --mode off --preview --duration 30
```

这30秒只观察。你自然站立、走动，队友看电脑是否持续显示人物骨架和“正在观察”。固定手机，让肩部和髋部一直清楚入镜；尽量使用之前测试可用的镜头和机位。出现“未检测到人/关键点不完整”，先调整取景，不进入正式报警测试。

这里没有自动动作提示音，按本页文字操作即可。

## 第2步：单独验证家属手机能收到一条测试警报

先让队友拿好安卓家属手机，App保持前台，并告诉他接下来是一条测试警报。然后运行：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\run_family_alarm.py --send-test --mode live --family $caremateFamily --src acceptance-interface
```

**这条会创建真实测试警报。** 电脑应显示“床头已收下报警”，队友应实际看到App警报，并确认声音/震动情况，随后点“知道了”。声音和震动来自**家属安卓手机**。

先给手机30秒观察窗口。若电脑已收到床头回执，家属手机仍无提示，此步记为手机端失败，先让队友查App版本、地址和通知，不进行倒地测试。

这一步绕过视觉，只验收通知通道；它通过仍不算视觉全流程通过。

## 第3步：由真实摄像头姿态触发一次完整闭环

第1、2步都通过后，在同一PowerShell窗口运行下面两行：

```powershell
$caremateRun = Join-Path 'code/data/fall_acceptance' ([DateTime]::Now.ToString('yyyyMMdd_HHmmss'))
& .\.venv\Scripts\python.exe -X utf8 .\run_family_alarm.py --phone-stream $caremateStream --mode live --family $caremateFamily --src acceptance-vision --preview --duration 300 --output $caremateRun
```

这条运行5分钟。保持手机固定；同一场景只留这一个检测入口，停止其他电脑/X5上的跌倒检测进程。你不用再手动运行发送警报命令。

按这个顺序做：

1. 先正常站立约5秒，让程序看到站立基准；再正常走动、缓慢坐下站起约20秒。此时不应新建跌倒警报。
2. 不用真的摔倒。若场地有安全的地面软垫，可由健康成年人平稳坐到垫上再侧躺，肩部和髋部仍保持在镜头内，在低处横躺约20秒。不要躺到已标成“床区”的区域。没有合适条件就跳过真人姿态触发，保留“未验收”，不要冒充完成。
3. 这属于**缓慢倒地姿态演示**。默认规则要求低处横躺持续12秒，且骨架连续可用；不是躺下一瞬间就必定报警。快速跌倒路径另有约2秒候选确认，本次不要求真人快速摔落来测试它。
4. 队友观察电脑：应出现“疑似跌倒已触发”，随后出现“床头已收下报警”及事件号。只有前者出现而后者未出现，说明发送未确认。
5. 另一个人确认家属手机出现本轮新警报，核对时间和来源`acceptance-vision`，记录实际提示、声音、震动，再在App点“知道了”。保持躺姿期间，不应重复新建同一事故警报。
6. 正常起身后保持直立约5秒，再按预览窗口Q/Esc结束；或者等待5分钟自动结束。测试先只做这一轮完整闭环，通过后再讨论追加轮次。

侧躺动作只验证“真实画面→姿态→缓慢倒地规则→通知”功能，不能用来声称真实意外跌倒准确率或快速跌倒检出率。坐在椅子上、只蹲下、人物离开画面，都不等同于满足倒地规则。

## 怎样判定本轮通过

下面五项要全部有证据，才写“前台全流程通过”：

| 项目 | 证据 |
|---|---|
| 真实iPhone画面与骨架持续可用 | 测试中能看见人物，控制台持续观察；不是离线骨架输入 |
| 视觉产生本轮事件 | `summary.json`的`detections`至少一条，记录触发原因`slow/rapid` |
| 床头收到同一事件 | `events`里`status:"bedside_accepted"`，保留event_id及alarm_id |
| 家属手机真的提醒 | 手机持有人确认新警报、时间、来源、界面/声音/震动；记录可用项 |
| 确认处理闭环 | App点击“知道了”后，本轮报警变为已确认，未持续重复触发 |

`phone_received:null`是程序如实没有手机送达回执，不是程序自动判断失败。必须补上手机持有人的现场确认。接口测试警报和视觉触发警报要分别记录，不能拿第2步的那一条替代第3步。

## 前台通过后，再单独测后台

让队友将家属App退到后台并锁屏，等约30秒，再运行一条独立的接口测试：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\run_family_alarm.py --send-test --mode live --family $caremateFamily --src acceptance-background
```

观察30秒有无系统通知、声音、震动。仍无响应就记录后台失败；点亮手机查看App自检行和警报记录，交给队友排查。后台失败不能写成视觉算法失败，也不能把“点亮后补看到”算成锁屏即时提醒成功。

## 故障发生在哪一段

| 现象 | 先检查什么 |
|---|---|
| 第0步失败 | 项目虚拟环境、MediaPipe、模型文件 |
| dry检查失败 | 同一网络、床头IP/8013端口、服务版本 |
| 画面连不上或无骨架 | MJPEG完整路径、手机App前台、固定机位、肩髋可见度、模型输入 |
| 有骨架，侧躺后没有事件 | 低处横躺是否连续满足、床区、取景/遮挡、规则状态；不能直接说整个通知链失败 |
| 有事件但发送失败 | 床头连接与回执，保留原event_id，避免换号重复报同一次事件 |
| 床头已收下，前台手机没提示 | 家属App连接地址、当前版本和前台轮询 |
| 前台可用，锁屏没提示 | App后台存活与系统通知权限；当前v1.4仍待现场验收 |

若iPhone输入临时无法继续，可先用电脑摄像头排查后半条链：将第1、3步命令中的`--phone-stream $caremateStream`换成`--camera 0`，其余参数照用。这只能记为电脑摄像头闭环通过，iPhone接入仍单独待验收。
