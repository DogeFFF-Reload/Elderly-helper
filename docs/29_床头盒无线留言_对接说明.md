# 29 床头盒无线留言：对接说明（回复《家属端 App 对接需求单》）

> 写于 2026-10-24 晚，分支 `software/comms`。床头盒 = 立创 S3 屏 + 地瓜 X5 手板（需求单里 10.153.47.252）。
> 结论：**家属端有后端（主脑），接收接口已经建好；X5 上的中继程序也已经写好**。S3 固件只要按第 3 节发 HTTP 就能通。
>
> **更新**：手板侧已经自带推送 / 拉取钩子（《对接卡 v2》），家属端改成手机 App、走公网不用热点——按 **`docs/30_回复_留言接入对接卡v2.md`** 配置即可。本文的局域网中继（`elder_link/relay.py`）留作同一热点时的兜底。

## 1. 无线怎么传

所有设备连**同一个 Wi-Fi**（现场热点或自带的随身路由器），全程 HTTP，不需要蓝牙、不需要公网：

```
 老人 → 家属
 S3 屏（留言键录音）──Wi-Fi──▶ X5 中继 :8014 ──Wi-Fi──▶ 主脑 :8000（笔记本）──▶ 家属端网页 /ui/family
                                 │ 先存盘再转发：断网不丢，连上自动按顺序补发
 家属 → 老人
 家属端网页（文字 / 语音）──▶ 主脑 ──▶ X5 中继每 2 秒来拉 ──▶ X5 喇叭（语音用 aplay 放；文字由 tts_player 念）
```

| 端口 | 谁 | 说明 |
|---|---|---|
| 8000 | 主脑（笔记本） | 家属端网页、接收留言、通知 |
| 8013 | X5 `arm_service` | 臂 / 手，**不动** |
| 8014 | X5 `elder_link/relay.py` | 新的床头盒中继：收 S3 的留言、转发、放家属留言、兜底收件箱 |

中继单独一个进程、单独一个端口，不碰臂和手的 8013。

**网络建议**：用一台随身路由器做现场热点，在路由器里给笔记本和 X5 绑定固定 IP（DHCP 保留），S3 固件和中继里写死这两个 IP，就不会出现“换了热点 IP 变了”的情况。

## 2. 音频格式

全系统统一 **WAV，16 kHz / 16 bit / 单声道**（就是需求单里手板录的格式）。家属端网页录音也按这个格式录，X5 用 `aplay` 直接放，不用装解码器。单条最长 60 秒（约 1.9 MB）。

## 3. S3 固件要做的（给写 S3 的人）

| 键 / 显示 | 请求（发给 X5 中继 `http://<X5 IP>:8014`） | 说明 |
|---|---|---|
| 留言键（按一下开始，再按一下或满 60 秒发送） | `POST /messages`，正文 = 录好的音频：裸 PCM（`Content-Type: application/octet-stream`）或 WAV（`audio/wav`）；可加 `?to=daughter`，默认 `all` 发给所有家属 | 回 `{"ok":true,"id":"msg_20261024_193005","duration":23.5}` → 屏显“已发送 ✓”。**回 ok 就代表已存盘，不会丢**，主脑暂时连不上中继会自己补发 |
| S3 没有麦克风时的留言键 | 第一下 `POST /record/start`，第二下 `POST /record/stop` | X5 用自己的 USB 麦克风录（需要 `arecord`） |
| 状态角标（每 2 秒） | `GET /status` → `{"recording","pending","master","unheard"}` | `pending>0`：“网络断了，连上后自动发”；`unheard>0`：“有 N 条家人留言” |
| 听留言键 | `POST /play` | X5 喇叭放最早一条没听过的家属语音 |
| 一键 120（长按 2 秒再发） | `POST /dial120` | 模拟拨号 + 通知所有家属（真拨号需要 4G 模块或云通信） |

固件注意（T5AI 那边踩过的坑，同样适用）：录音缓冲放 PSRAM；裸 PCM 里有 0x00，**不要用会按 `strlen` 算长度的 HTTP 封装**，用底层 `esp_http_client` 自己填 `Content-Length`；HTTP 请求放主循环里串行发，不要在 LVGL 回调里发。

## 4. X5 上要跑的

```bash
cd code
python3 -m elder_link.relay --master http://<笔记本 IP>:8000 --box-id hand-A      # 床头盒中继，默认 :8014，存盘 ~/caremate_msgs
python3 -m voice.tts_player --server http://<笔记本 IP>:8000                     # 家属文字留言念给老人听（已有）
```

依赖：`sudo apt install alsa-utils`（`aplay` 放音、`arecord` 录音）。中继只用 Python 标准库。

联调（在笔记本上就能测）：

```bash
curl -X POST --data-binary @msg.wav -H "Content-Type: audio/wav" http://<X5 IP>:8014/messages
curl http://<X5 IP>:8014/status
```

浏览器打开 `http://<X5 IP>:8014/messages/inbox` 是兜底收件箱（需求单第 3 节那个网页），同一热点的手机都能直接听。

## 5. 对需求单第 4 节的回答

1. **有后端**：主脑 `master_service`（笔记本 :8000）。接收接口 `POST http://<笔记本 IP>:8000/api/voice_msg`，**需求单里的 multipart 格式原样接收**（`audio` 文件、`time`、`duration`、`elder`），也接受裸 WAV 正文 + `?from=elder&to=all&dur=23.5`。推荐走 X5 中继（第 4 节），它会存盘、重试，S3 不用管网络。
2. **怎么通知家属**：家属端是网页（`/ui/family`），每 0.4 秒拉一次主脑，新留言到了**响提示音、自动播放**，消息列表里有红点。网页关了收不到推送（演示阶段够用；上线需要做 App 推送或公众号模板消息）。
3. 不适用（有后端）。
4. **平台**：浏览器网页，不用装 App。手机打开 `http://<笔记本 IP>:8000/ui/family?as=daughter`。注意：手机浏览器在 http 下**能收、能播、能打 120**，但**不能用麦克风**（录语音、语音通话要 HTTPS 或在笔记本上用 localhost 打开）。
5. **绑定关系**：演示阶段按“一个老人 → 所有家属”广播（`to=all`，默认就是这样），家属名单在 `config.py` 的 `contacts`（女儿、儿子）。
6. **家属手机连哪个网**：演示用现场同一个热点，走局域网。
7. **公网**：演示不需要。以后要“家属在外地也能收”，把主脑放到一台云主机上，X5 中继的 `--master` 改成云主机地址即可，接口不变。

## 6. 同一批改动（和床头盒相关的）

- **识别到摔倒立刻报警**：视觉一报倒地，所有家属马上收到“可能摔倒了，正在确认情况”（`fall_alert`），不再等 5 秒询问结束；老人说“没事”会补发“警报解除”。询问、按 SOS、紧急通话照旧。
- **一键 120**：床头屏、床头盒长按 2 秒；家属端手机上直接打开拨号盘（已填好 120，要自己按拨出）。
- 家属的**文字留言**到了会自动念给老人（tts_player），床头屏上每条都有“读给我听”可以再念一遍；**语音留言**自动放（床头屏开着就屏幕放，否则 X5 喇叭放）。
