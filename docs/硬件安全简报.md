# 硬件安全简报（30 分钟，第一次碰硬件前全员过一遍）

> v2.5 §7.2 第 4 项。硬件负责人讲，另外三人每人亲手做一遍"三级停止"。开机、关机的具体命令见《开机步骤》。

## 1. 哪里会伤人（5 分钟）

| 东西 | 风险 | 记住一句话 |
|---|---|---|
| 机械臂 Panthera-HT | 大臂 / 小臂关节（J2/J3）最大约 36 Nm，伸直约 0.6 m；J1 底座**没有机械限位**，转过头会拉坏底座线缆 | 通电时不进它够得着的范围 |
| 臂没力的时候 | 阻尼（程序退出、越界锁定）挡不住重力，抬着的臂会慢慢往下沉；**断 24V 会直接失力往下掉** | 停之前先让它回 rest（收拢），有人扶 |
| 仿生手 ×2 | 手指会夹；轻握安抚已限到半握、300 g | 手指缝里不放手指 |
| 24V 电源 | 端子裸露 | 通电时不碰金属端子，接线先断电 |
| X5 | 供电不足会掉电重启（装包时掉过一次） | 用 5V/5A 电源，别从笔记本 USB 取电 |

## 2. 三级停止（5 分钟讲 + 每人按一遍）

1. **操作台 `Esc`（软件急停）**：臂当场停住、保持姿态，双手停住，之后不再收任何动作。保命链（通知家属）照常走软件。解除只能点"解除急停"并确认现场安全。
2. **物理急停按钮**：位置【待硬件确认】。`Esc` 之后臂还在动，就拍它。
3. **断臂的 24V**：最后一道。断了臂会掉，先确认臂下方没人、没有手。

## 3. 红线（违反一条就停下来找硬件负责人）

- 不跑 SDK 自带的示例脚本，尤其是直接调电机的：它们绕过关节限位和越界锁定。
- 不置零（`0_robot_set_zero.py`）：零点错了，所有限位一起偏，J1 会转过头。
- 不改 `Follower.yaml` 的关节限位、不改 `motor_timeout_ms`（必须是 0）。
- 一次只开一个控制臂的程序（`arm_service`、示教工具二选一，SDK 有锁，第二个会直接报错，别想办法绕过）。
- 臂通电时不用手推关节；只有示教时，在工具提示"重力补偿已开始"之后才能推。
- 不动控制盒和蓝盒的拨码开关，不拆外壳。

## 4. 出了状况怎么办（10 分钟）

| 看到 | 先做 | 再做 |
|---|---|---|
| 臂往人这边走、动作不对 | `Esc` | 找硬件负责人看日志，别直接重启 |
| 窗口里"电机层越界锁定" | 扶住臂（已经阻尼，会下沉） | 对着零位标记把关节推回范围，重启 `arm_service` |
| "另一个程序正在控制机械臂" | 不要删锁文件 | 找到另一个程序（示教工具、脚本）关掉它 |
| 臂在慢慢往下沉 | 扶住 | 它在阻尼，没在执行指令；按《开机步骤》重新起服务 |
| X5 死机、断电 | 别慌：电机会一直执行最后一条位置指令，原地保持 | 扶住臂再断 24V |
| 有人被夹 | 拍物理急停 / 断 24V | 先把人弄出来，再管设备 |

## 5. 演示当天（5 分钟）

- 硬件负责人站在臂旁，**手不离急停**；软件在操作台，`Esc` 随时按。
- 演"老人"的同学躺的位置要和 `arm_skills.json` 里的禁区对得上：头在禁区里，手在递药点附近。换了床位就重新量、重新跑 `python tests/run_all.py arm`。
- 评委、观众离臂 1 m 以外。
- 臂不用的时候停在 rest。
