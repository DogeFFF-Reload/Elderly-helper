# RH56F2 实测记录（2026-10-23，笔记本 + 蓝盒 + 手#2）

> 给硬件同学：这只手现在**能通信、读得到部分数据，但还不能动**。原因是 F2 的寄存器地址和我们手头的手册对不上。
> 全程只发过**读**指令，没写过任何寄存器。驱动里 `rh56_register_map.VERIFIED` 仍是 `False`（真机只读）。
> 原始扫描数据在 `docs/rh56f2_scan/`。

## 1. 测试环境

| 项 | 实际情况 |
|---|---|
| 手 | 因时 RH56F2（型号后缀 E2/E4 未确认） |
| 转换器 | 蓝盒，丝印 `COM-USB-CANFD-01`。电脑上显示为 `USB-SERIAL CH340`（VID 1A86 / PID 7523），这台笔记本上是 **COM7**（COM3~6 是蓝牙口，别选错） |
| 供电 | 24V 电源砖 |
| 程序 | 仓库 `software/hand-driver` 分支的 `hand_controller/rh56f2_driver.py`。**没有用** WeChat 发来的 kit 里的 `arm_service.py` / `START_HAND.bat` |

## 2. 协议：确认可用

- **因时自有 RS485 协议（EB 90）能通**：115200 波特率、8N1、手 ID = 1。帧格式见《RH56用户手册V1.09cn》§2.2，驱动已按它实现。
- **Modbus RTU 不通**（发过 1 条 FC03，没回应）。kit 里的驱动就是 Modbus 加占位地址，所以 kit 那套在这只手上不可能动。
- 第一条成功的收发（读 1546 起 12 字节）：
  ```text
  TX eb 90 01 04 11 0a 06 0c 32
  RX 90 eb 01 0f 11 0a 06 ff ff ff ff ff ff ff ff ff ff ff ff 25
  ```
  包头 `90 EB`、ID 1、长度 15、命令 0x11、地址 1546 回显、校验和 0x25，全对。
- **回话的是手本身**：拔掉 24V 后同一条指令完全没回应；插上就回。

## 3. 地址：F2 和 V1.09 手册不一样

V1.09 写的 1486~1617（角度设置 / 实际角度 / 力度 / 故障 / 状态 / 温度）在 F2 上**全部读回 0xFF**。所以按 0~4031 做了只读扫描（64 字节一段，再对 1152~2175 按 12 字节一段复扫）。

对照依据：官方《灵巧手上位机软件操作手册》里 RH56FX 连接成功的截图。上电后设置角度 -1 ×6、设置速度 2000、设置力度 600、上电默认速度 2000、上电默认力度 600、实际角度 1572~1764、温度 36~42℃、故障码 0。

| 地址（十进制，字节） | 读到的值（按 short，低字节在前） | 推测含义 | 把握 |
|---|---|---|---|
| 1100–1111 | 36, 36, 34, 34, 30, 34 | **温度 ℃**（和截图规律一致：四指相同、拇指弯曲最低） | 高 |
| 1112–1123 | 0 ×6 | 故障码 | 中 |
| 1088–1099 | 7 ×6 | 状态码 | 中 |
| 1056–1067 | -1 ×6 | 角度设置值（上电后为 -1） | 中 |
| 1032–1043 | 600 ×6 | 上电默认力度 | 中 |
| 1068–1079 | 600 ×6 | 力度设置值 | 中 |
| 1044–1055 | 500 ×6 | 不明 | 低 |
| 1024–1031、1080–1087 | 2000 ×4（各只有 4 个） | 像速度，但个数对不上 6 个关节 | 低 |
| 1124 起 | 每 8 字节一组重复（31248, 9729, 4209, …） | 像各电缸序列号 | 中 |
| 192 | 1 | 可能是手 ID | 低 |
| 0–31 | `aa 55`、1、4118、80、21、26、10、19、4… | 设备信息头（版本 / 日期？） | 低 |
| 40–51 | 6 ×6 | 不明 | 低 |
| 512–575、2016–2051、2528–2913 | 一步一组：6 个角度 + 6 个速度（2000）+ 6 个力度（620 等）+ 间隔（1000/2000） | **手里存的动作序列**。角度最大到 2000，说明 F2 角度量程大概是 0~2000，不是 V1.09 的 0~1000 | 中 |
| 704–1023、2176–2527、3008–4031 等 | 全 0 | 不明（可能是没在用的区） | — |

**没找到**：实际角度（截图里那组 1572~1764 的数，0~4031 里都没出现）。没找到它，就没法确认"写角度 → 手动了没有"，所以不能打开 `VERIFIED`。

## 4. ⚠ 越界读会把手卡死，恢复要按顺序断电

- 读 **4032** 起的地址时手没回应，**之后所有读指令都不回**。
- 只拔插蓝盒 USB **恢复不了**；只换串口也不行。
- 恢复办法：**24V 和蓝盒 USB 都断开 → 先插蓝盒 USB → 再插 24V → 等 10 秒以上**。按这个顺序做完，读指令马上恢复正常。
- 另外：24V 没插时连发的读指令都没人应答，之后即使插上 24V 也要按上面的顺序重来一遍。

对驱动的要求（改 `rh56f2_driver.py` 时照做）：

1. 只读确认过有效的地址，**绝不读 4032 及以上**，也不做盲扫。
2. 一旦"没回应"，**不要自动重试**；直接报"手不回话：按 24V + 蓝盒断电重启"。
3. 角度量程按 F2 的来（看起来是 0~2000），`to_raw` 和 `poses.JOINTS` 的换算要跟着改。
