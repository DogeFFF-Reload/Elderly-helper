# 报警链路修复与 Gemini 一次复核

## 现在完成了什么

更新：2026-10-24。按用户选择，先由 Codex 修复和验证，再让 Gemini 在现有网页会话里做一次复核。Gemini 尚未给出本轮审查意见。

这次修的是能在电脑上复现的软件问题：

| 问题 | 现在的行为 |
|---|---|
| 120 确认已过期，但定时检查尚未运行时仍能确认 | 收到确认时立即检查截止时间，过期或正好到期均取消，不产生模拟拨号记录 |
| 老人已表示没事，旧的 120 确认窗仍残留 | 语音或绿键解除当前事故时，一并清除旧确认窗 |
| “确认不要打”可能按开头的“确认”处理 | 同一句里取消词优先，取消模拟拨号 |
| “我不是没事”“我没事但起不来”可能误解除报警 | 已覆盖的否定表达和明确求救词不再当作报平安；询问中升级 SOS，已有 SOS 保留 |
| 血压确认已过期，定时检查前仍能记账 | 确认时检查截止时间，过期读数丢弃 |
| 家属端、大屏和操作台把动作请求或回执写成真机已完成 | 区分等待回执、已接收但完成待确认、模拟动作、失败、急停；不凭 HTTP 成功推断实物动作完成 |
| 网页和台词容易让人误以为已发短信或打电话 | 明确写为家属演示页面本地记录；120 明确为模拟；通知说明台词固定，不交给 LLM 润色 |
| 家属端只有用药状态变化时可能不刷新 | 开关、服药记录及动作状态加入刷新条件 |
| 错误 JSON 变成空请求，可能默认替首位家属确认 | 错误或非对象 JSON 返回 400，超过 1 MiB 返回 413；家属确认必须明确携带有效联系人 |
| 无效事件游标可能断开 HTTP 连接 | 非整数或负数游标返回 JSON 400，服务仍可继续使用 |
| 无效整数配置可能抛出未处理的溢出异常 | 返回配置错误，整批参数不生效 |
| 跌倒平滑参数为 0 会除零，坏关键点可能污染后续判断 | 启动时校验有限数字、正时长、角度和床区；坏关节视为不可用，不污染下一帧的正常骨架 |

没有修改跌倒规则的默认阈值。原来“快速倒地候选出现后，持续看不到人仍可能确认”的策略保留；画面超过间隔上限的处理仍由输入质量层负责。关键词保护只覆盖规则中列出的表达，不能宣称理解了所有中文否定、求救或口音。

## 你现在要做什么

**你现在只需做一次文件上传，不需要安装程序、登录 Antigravity、配置 API key 或重新采集动作。**

1. 打开你原来已经登录的 [Gemini 网页](https://gemini.google.com/)。
2. 上传本机 `sync_bridge/to_gemini/FINAL_REVIEW.zip`，粘贴旁边的 `发给Gemini的文字.txt`。不要上传旧的 `001_alarm_review_fe0091e.zip`。
3. Gemini 回复后，把完整答复复制给 Codex；如果有附件就保存后交给 Codex。我会核对结论、修复有依据的问题，再运行相关验证。当前没有能自动读取这个网页聊天的连接器。

代码会按此前授权提交到 GitHub；包内 `manifest.json` 记录最终提交号和各文件校验值，本机 `packet_receipt.json` 记录整个 ZIP 的校验值。只发复核 ZIP 即可，不必把真实个人录制交给 Gemini。
