# 45 · 留言 wav 的 rms 分段实测结论

> 起因：反馈"留言听起来断断续续，怀疑麦克风坏/录音丢段"。
> 用数据链路闭环排查后结论：**麦克风无故障，是说话节奏**。实测日期 2026-10 下旬。

---

## 一、排查方法（可复用）

1. **先验 wav 头**：板上留言 wav 文件头恒为 **44 字节标准 head，16kHz / 16bit / 单声道**——格式层无异常；
2. **分段 rms**：对 wav 按 ~200ms 窗逐段计算 RMS（响度），把整条留言做成"响度剖面"；
3. **对照说话节奏**：剖面低谷应与停顿/换气位置对齐，而不是随机塌陷。

## 二、数值画像（正常说话）

| 状态 | rms 量级 |
|---|---|
| **正常说话段** | **2000 ~ 4000** |
| 停顿/换气/句间气口 | 接近 0 的低谷，位置与讲话节奏一致 |
| 空录/无效段 | < ≈200 |

实测结论：低谷位置**全部落在句子停顿处**，逐段对得上一句一停的自然节奏——所谓"断续"就是用户本人的说话节奏（慢、多停顿），不是采集或传输丢数据。

## 三、判定规则（沉淀）

- rms < 200 且持续整段 → 空录，提示"按住再说话"；
- rms 峰值段 < 2000 → 音量偏低，可在固件侧适当抬增益；
- **正常值域 2000~4000**，作为后续"说了没说"自动判别的基线；
- 判"说了没说"只看全文 rms 总能量不够稳——**必须分段**，防止一声咳嗽顶起总能量造成误判。

## 四、后续动作

- 信箱自动判"空段并提示重说"可以基于此规则实现（暂未排期）；
- 播放断续如需进一步优化，走 App 预下载秒播（v1.9，见 `43_版本线速查`），与录音质量无关。
