# CareMate 现场执行清单（睡眠期间可直接接续）

更新时间：2026-10-24。仓库执行端唯一入口是
`code/hand_controller/arm_service.py`；`caremate_d_kit` 里的同名服务不启动。

## 当前已确认

- 主脑 HTTP 契约、kit 兼容路径、手机跌倒保底链路均已接入仓库。
- RH56 驱动实现 FC03/FC06/FC16、CRC、从站 ID 1/2 和双手/同总线模式。
- `gentle_hold` 与 `comfort_rhythm` 现在都落到手 #2 的同一真实序列。
- Panthera SDK 未提供，因此真实机械臂动作会明确失败，不会把日志当成物理完成。
- 当前寄存器表仍是占位值：`rh56_register_map.py` 的 `PROVISIONAL=True`。
- 本机当前没有可见串口；没有进行任何真实写入。

## P0：拿到硬件后先做这几步

1. 在连接蓝盒的机器安装依赖：

   ```powershell
   cd <仓库>\code
   python -m pip install -r requirements-hardware.txt
   python -m tools.hardware_preflight
   ```

2. 按 `docs/10_RH56F2驱动笔记_待核对.md` 对照实际 RH56F2 固件手册，逐项确认目标、速度、状态、控制寄存器、原始量程和关节顺序。

3. 只修改 `code/hand_controller/rh56_register_map.py`：更新地址/量程，确认无误后将 `PROVISIONAL=False`。然后记录手 #1/#2 是同一串口不同 ID，还是两个串口。

4. 再次运行只读检查；real 检查必须显示“条件满足”：

   ```powershell
   python -m tools.hardware_preflight --mode real `
     --hand1-port COMx --hand2-port COMx --require-real
   ```

5. 启动仓库服务并做低风险三姿态：

   ```powershell
   $env:MOCK_SERIAL="0"
   $env:RH56_REGMAP_CONFIRMED="1"
   powershell -ExecutionPolicy Bypass -File deploy/start_hand.ps1 `
     -Mode real -ConfirmRegisterMap -Hand1Port COMx -Hand2Port COMx
   powershell -ExecutionPolicy Bypass -File deploy/hand_demo.ps1
   ```

   三姿态只验收张开、挥手、点赞；任何异常先断 24V，不改蓝盒 DIP，不碰带电端子。

## P1：真实手链验收顺序

按下面顺序逐项记录 HTTP、手号、物理结果和 `/status`：

```text
fingers_5       hand=1   低风险张开
release         hand=1   回到松开
thumbs_up       hand=1   点赞
pose/rock       hand=1   猜拳石头
pose/comfort_rhythm?hand=2   手#2 轻握节拍
pose/wave       hand=1   慢序列挥手
```

低风险姿态全部稳定后，再接主脑跌倒链。`press_sos`、`handover_med`、`reset`
在 Panthera SDK 未接入前只能验收“被拒绝且原因清楚”或 mock 演示，不能宣称臂已完成。

## P1：Panthera SDK 到手后的唯一改动点

向厂家拿齐 SDK 包（Linux/aarch64）、设备节点、授权文件和慢速点动示例。
真臂后端已在 `code/hand_controller/arm_backend.py`：按 `docs/开机步骤.md` 先 `--probe` 只读关节角，
再用 `arm_teach.py` 示教 `taught: false` 的点位、`arm_selftest` 小角度自检。启动时设置 `ARM_BACKEND=panthera`，主脑和视觉接口保持不变。

## P2：手机跌倒保底

手机 IP Webcam 和主脑在同一网络。先 `--arm 0` 记录静止、摆手、缓慢倒地的
能量，再按 `docs/21_交接_手机摄像头组.md` 公式定阈值；最后 `--arm 1` 连续完整触发三次，记录误报/漏报。哨兵只能 POST `/mock/fall`，不能直接调用 8013。
