> 更新于 2026-10-24。本文取代本文件旧版的安卓安装、`/shot.jpg` 和变化能量阈值标定步骤。
> 当前不要求补采数据，不连接真实硬件。手机默认只观察；离线演示使用独立本机主程序和模拟执行端。

## 2. 现在没有设备时，怎么演示

在仓库 `code/` 目录只运行：

```powershell
python -m vision.rehearsal
```

该命令不需要手机、姿态模型或 OpenCV，也不需要另开主程序、机械臂服务、TTS 或 ASR。它只启动绑定 `127.0.0.1` 随机端口的独立主程序，忽略本机配置和环境变量中的真实执行端、在线大模型设置，执行完自动退出。

内置检查包含：快速倒地、坐下、弯腰、绊倒后恢复、坐姿倒地、床区、缓慢滑倒、遮挡后倒地、再次倒地，以及没人、低可见度和输入时间缺口。所有内置坐标均为合成数据。

终端给出：

- `report.html`：直接双击打开的中文结果；
- `report.json`：事件、主程序状态、输入质量、模拟动作和逐项检查；
- 同名 ZIP：可直接发给队友的结果包；
- `keypoints/`：标为 synthetic 的合成骨架，供重复回放。

默认结果在 `code/data/vision_rehearsal/<批次>/`，这些运行数据不进入 Git。命令返回非零表示有检查未通过；不要将失败的报告当成验收通过。

## 3. 以后有骨架文件时，怎么复现问题

手机观察入口保存的 `keypoints.jsonl` 可以离线回放到同一个模拟主程序：

```powershell
python -m vision.rehearsal --keypoints "data/phone_pose/批次/keypoints.jsonl"
```

回放始终使用模拟执行端，不需要手机连接。原文件不被修改；默认没有动作真值标签，报告只说明实际触发及链路情况，不根据文件名猜测是否应当报警。软件链路检查通过不代表识别正确。

`phone_calibration` 中的 `samples.csv` 不是骨架文件，不能用于这个命令。

## 4. 以后到现场，你只负责视觉和软件

当前不需要执行本节；等具备设备条件再做。

1. 使用已经验证能供 MJPEG 的 iPhone 应用，保持前台；手机固定，人物尽量完整入镜。沿用当前镜头与摆放条件，改变镜头或机位后的效果另行确认。
2. 手机和电脑在同一网络，使用 App 给出的完整 MJPEG 地址。不要猜 `/shot.jpg`，也不需要安装安卓 IP Webcam。
3. 在仓库根目录已经准备好 `.venv` 和模型时，进入 `code/`，运行本地观察：

   ```powershell
   ..\.venv\Scripts\python.exe -m vision.fall_bridge --phone-stream "http://<手机主机名或IP>:8081/" --phone-username "<账号>" --phone-password "<密码>" --duration 60 --preview
   ```

   地址、端口和凭据替换为 App 实际显示的值。也可在当前终端用 `PHONE_USERNAME` / `PHONE_PASSWORD` 提供凭据。此入口不向主程序发送任何事件。

4. 先确认身体关键点稳定、正常站立/走动/坐下没有明显异常。按 `q` 或 Ctrl+C 停止，记录会保留。当前不要求额外进行完整多轮采集。
5. 把新保存的骨架用第 3 节命令回放，连同结果 ZIP 和现象说明交给软件队友。真正启用实时上报及真实设备联动，需另行完成现场验收。

公开静态图片与合成动作不能替代真实场景验收。不要使用旧文档的能量阈值公式直接宣布跌倒识别有效。

## 5. 状态提示是什么意思

| 提示 | 含义 | 排查方向 |
|---|---|---|
| 正在观察 / observing | 本帧有可用躯干关键点，规则正在判断 | 继续观察；不等于已验证动作类别 |
| 未检测到人 / no_person | 收到画面，但模型没找到人 | 取景、遮挡、人物大小与光照 |
| 关键点不完整 / pose_unavailable | 找到部分人体，但肩/髋关键点不足 | 全身取景和关键部位可见度 |
| 正在确认 / candidate | 动作进入疑似倒地候选 | 查看后续动作、时间线和规则理由 |
| 疑似跌倒已触发 / suspected_fall | 本地规则产生一次疑似事件 | 当前手机入口只记录，不向主程序上报 |
| 输入中断 / input_error | 断流、画面无效或录制时间无效，观察已停止 | 先排查输入；不会标为成功 |
| 画面间隔过长 | 相邻处理帧时间缺口超过 3 秒 | 重新开始动作计时，避免用缺失时间确认倒地 |

已报告的疑似跌倒不会因时间缺口自动重新布防。持续收到新画面但看不见人，与根本没有新画面是不同情况；前者保留已有遮挡规则。检测到人的帧比例表示输入可用情况，不能当准确率。

## 6. 硬件队友负责什么

- 当前阶段不需要硬件队友连接或操作设备。
- 将来由硬件队友确认真实机械臂、机械手、电源、急停和现场动作。
- 执行端始终使用仓库 `code/hand_controller/arm_service.py`，不用 kit 自带版本。
- 视觉只处理画面、坐标和主程序接口，不直接调用执行端或改串口/寄存器。
- 手机实时上报尚未开放；本次成果是观察记录与隔离的模拟联调，不代表真机闭环完成。
